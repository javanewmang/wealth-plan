# A股智能分析系统（安卓 + Web + 后台）需求分析与架构方案（V2-按你反馈修订）

> 目标：先完成需求分析与架构设计，待你确认后再进入编码与测试实现阶段。

## 1. 项目目标与范围

### 1.1 目标
- 打造一款面向 A 股用户的智能证券分析平台，能力对标“大智慧”类产品的核心功能。
- 同时支持：
  - 安卓客户端（Android）
  - 浏览器端（Web）
  - 后台管理与业务服务（Backend）
- 引入大模型（OpenClaw）能力，使用户通过自然语言指令实现：
  - 自动盯盘
  - 消息提醒
  - 自动分析与解释

### 1.2 建设原则
- 生态维护性优先（社区活跃、人才供给充足、版本迭代稳健）。
- 性能与并发能力优先（低延迟行情处理、高并发推送）。
- 扩展性优先（后续可平滑新增策略、模型、市场、终端能力）。

### 1.3 本期范围（建议）
- 行情展示、分时/K线、股票搜索、自选股、基础指标分析。
- 智能助手（OpenClaw）+ 指令编排（盯盘/提醒/分析）。
- 用户、订阅、消息中心、后台运营。
- 不含：自动交易下单（如后续涉及，需额外合规与风控设计）。

## 2. 需求分析

## 2.1 用户角色
- 普通投资者：查看行情、分析个股、设置盯盘和提醒。
- 进阶投资者：自定义条件/策略、组合分析、批量监控。
- 运营管理员：管理用户、内容、消息模板、模型策略开关。

## 2.2 功能需求（对标同类软件）

### A. 行情与市场数据
- A股实时行情（沪深京，分级支持）。
- 分时图、K线（日/周/月/分钟级），成交量、换手率等。
- 板块/概念/行业排行，资金流向（若数据源支持）。
- 涨跌榜、异动榜、热门榜。

### B. 个股分析
- 基础面信息（财务摘要、公告、研报聚合）。
- 技术指标（MA、MACD、KDJ、RSI、BOLL 等）。
- 多维度评分（可解释：趋势、波动、资金、估值）。
- 风险提示（高波动、停牌、ST、公告事件）。

### C. 自选与组合
- 自选股分组管理、排序、标签。
- 组合看板（收益率、回撤、行业分布）。
- 同步多端数据（安卓/Web 一致）。

### D. 智能盯盘与提醒（核心差异化）
- 规则盯盘：
  - 价格突破/跌破
  - 成交量放大
  - 指标金叉死叉
  - 板块联动
- 通知渠道：App Push、站内信、邮件（后续可加短信/企业微信）。
- 提醒去重、限频、静默时段。

### E. 大模型智能体（OpenClaw）
- 自然语言指令：
  - “帮我盯住贵州茅台，跌破 1600 提醒我”
  - “分析一下新能源板块今天异动原因”
- 指令理解与结构化（NL -> DSL/任务编排）。
- 自动分析报告生成（结论 + 依据 + 风险）。
- 多轮对话上下文（会话记忆，用户偏好）。
- 模型安全：敏感词过滤、投资建议免责声明、输出审计。

### F. 后台管理
- 用户与权限、套餐与额度（盯盘数、调用次数）。
- 消息模板管理、运营公告。
- 模型配置管理（prompt、工具开关、限流）。
- 数据质量监控（行情延迟、缺失、错误率）。

## 2.3 非功能需求
- 可用性：核心服务可用性目标 99.9%（后续可上 99.95%）。
- 性能：
  - 行情写入 -> 用户端可见延迟 P95 < 1.5s（流式场景）
  - 盯盘触发 -> 通知下发 P95 < 3s
- 并发：
  - 初期 5~10 万 DAU，峰值在线连接 2~5 万；
  - 架构预留水平扩展到百万级连接。
- 安全与合规：
  - 数据传输 TLS；
  - 鉴权 OAuth2/JWT；
  - 日志脱敏；
  - 投顾合规边界提示（不构成投资建议）。

## 2.4 约束与风险
- 行情数据版权与商业授权成本。
- 大模型输出稳定性与幻觉风险。
- 推送链路在不同厂商通道下到达率差异。

## 3. 技术选型（维护性 + 性能 + 扩展）

## 3.1 客户端

### Web
- **React + TypeScript + Next.js（App Router）**
  - 生态成熟，SSR/CSR混合能力强，便于SEO与首屏性能。
- UI：Ant Design（固定选型，建议 Ant Design Pro + 轻定制）。
- 图表：ECharts（金融图表生态成熟）。

### Android
- **Kotlin + Jetpack Compose**
  - 官方主推，长期维护性最好，开发效率高。
- 网络层：Ktor/Retrofit；状态管理：ViewModel + Flow。
- 推送：FCM + 国内厂商通道聚合（如个推/极光可选）。

> 说明：若希望降低双端研发成本，备选 Flutter（同时覆盖 Android/Web），但在复杂金融图表与Web SEO方面通常不如原生组合灵活。

## 3.2 后端
- **Java（主服务，Spring Boot 4.x + Spring Cloud）+ Python（AI编排/模型适配）**
  - Java：企业生态成熟、长期维护性强，适合复杂业务与高并发服务治理。
  - Python：AI生态强，便于接入 OpenClaw 与工具链。
- API 协议：
  - 外部：REST + WebSocket（行情推送）
  - 内部：gRPC（服务间高效通信）
- Java 关键组件建议：
  - ORM：MyBatis-Plus / JOOQ（复杂查询场景更可控）
  - 安全：Spring Security + JWT/OAuth2
  - 服务治理：Resilience4j（熔断、限流、重试）
  - 消息：Spring for Apache Kafka

## 3.3 数据与中间件
- OLTP：PostgreSQL（用户、配置、业务数据）。
- 缓存：Redis（行情热点、自选缓存、会话缓存、分布式锁）。
- 消息流：Kafka / Pulsar（二选一，建议 Kafka，生态更广）。
- 搜索：OpenSearch/Elasticsearch（股票检索、公告检索、日志检索）。
- 时序数据：TimescaleDB / ClickHouse（行情历史与分析查询）。

## 3.4 云原生与运维
- 容器：Docker + Kubernetes。
- 网关：Kong / APISIX（鉴权、限流、审计）。
- 可观测：Prometheus + Grafana + Loki + OpenTelemetry。
- CI/CD：GitHub Actions / GitLab CI + ArgoCD。

## 3.5 AI（OpenClaw）深度集成
- 统一 LLM Gateway：屏蔽模型差异，支持模型路由与降级。
- Agent Orchestrator（多工具编排）：
  - 指令理解 -> 任务拆解 -> 工具选择与执行 -> 结果校验 -> 汇总输出。
- 工具链（Tooling）建议首批内置：
  - 行情工具（实时/历史K线、盘口、异动）
  - 指标工具（MA/MACD/KDJ/RSI/BOLL 计算）
  - 新闻与公告工具（事件抽取、情绪标签）
  - 用户策略工具（规则保存、回放、触发记录）
- Prompt、工具、工作流版本化管理（支持灰度和回滚）。
- 成本与质量治理：缓存、限流、重试、输出评分、人工抽检。

## 4. 参考架构设计

## 4.1 分层架构
1. 终端层：Android / Web。
2. 接入层：API Gateway + BFF（Web-BFF / App-BFF）。
3. 业务层：用户服务、行情服务、分析服务、盯盘服务、消息服务。
4. AI层：OpenClaw Adapter + Agent Orchestrator + 工具服务。
5. 数据层：PostgreSQL、Redis、Kafka、搜索与时序库。

## 4.2 核心链路（示例）
- **行情链路**：数据源 -> 行情接入服务 -> Kafka -> 实时计算/聚合 -> Redis/WebSocket Hub -> 客户端。
- **盯盘链路**：用户规则/LLM指令 -> 规则引擎 -> 实时事件流匹配 -> 触发 -> 消息服务。
- **AI分析链路**：用户问题 -> Agent -> 调用指标/新闻/财务工具 -> OpenClaw生成 -> 审计后返回。

## 4.3 可扩展性设计点
- 插件化指标引擎（新增指标无需改核心流程）。
- 规则引擎 DSL 化（规则可配置化管理）。
- AI 工具注册中心（新增工具以配置驱动接入）。
- 多租户与配额体系（后续商业化）。

## 4.4 高并发与高可用关键措施
- WebSocket 网关无状态化 + 水平扩容。
- Kafka 分区与消费者组扩展。
- Redis Cluster 热点分片。
- 读写分离与异步化（查询与计算解耦）。
- 限流/熔断/降级（保护核心链路）。
- 多机房容灾（后续阶段）。

## 5. 推荐实施路线（分阶段）

## Phase 3（规模化）
- 多模型路由、成本优化。
- 分布式规则计算与更高并发接入。
- 灰度发布、混沌演练、容灾升级。
